# 강의 녹음 · 로컬 STT 개발 계획

작성: 2026-09-11. 제품 목표는 한국어 강의를 장시간 녹음하면서 자막을 읽고,
PDF 페이지·마크다운 필기를 녹음 시간에 연결해 복습하는 것이다.
‘출시 목표’의 수치는 목표이며, 실제 측정은 아래 ‘구현 및 검증 현황’에 분리했다.

## 설계 결정

- 과목마다 녹음 탭을 열고 그 안에서 여러 녹음 세션을 관리한다.
- 첫 입력은 마이크. 수집 수명은 탭 컴포넌트와 분리해 탭을 닫거나 과목을
  바꾸어도 계속 녹음한다. 앱 종료/입력 장치 상실은 중단으로 명시한다.
- 16 kHz mono PCM을 작은 청크로 디스크에 먼저 기록한다. 인식기는 별도
  utility process에 한 번 로드한다. 수신 확인과 순서 번호로 누락을 감지한다.
- 추론이 입력보다 느릴 때 음성을 버리지 않고 디스크를 큐로 사용한다.
  메모리는 고정 크기 창으로 제한하고 자막의 실제 지연을 표시한다.
- 자막은 수정 가능한 임시 결과와 확정 결과를 구분한다. 확정 결과와
  연결 앵커는 증분 저장한다. 녹음과 자막의 시계는 수신 샘플 수를 사용한다.
- 모델은 사용자가 선택하여 다운로드한다. 고정 URL·크기·해시 검증,
  취소·재시도, 설치 완료 마커를 사용한다. 앱 재시작 후에도 설치를 인식한다.
- 사용자 음성은 외부로 보내지 않는다. 클라우드 STT는 별도 후속 기능이다.

## 모델과 엔진 선택

사용자 지정에 따라 **Whisper large-v3-turbo FP16을 기본 강의 모델로 확정**했다.
`@fugood/whisper.node` 1.1.3의 whisper.cpp 실행기를 사용하며 Apple Silicon에서는
Metal + Flash Attention, 다른 플랫폼에서는 CPU를 요청한다. API 모델로
대체하지 않는다. 기존 Zipformer/SenseVoice는 명시적으로 선택할 수 있는
이전 모델로 유지하며, 설치돼 있다는 이유로 기본 모델을 자동 변경하지 않는다.

| 후보                                        | 역할                                 | 검증할 점                                |
| ------------------------------------------- | ------------------------------------ | ---------------------------------------- |
| sherpa-onnx / Zipformer Korean int8         | 한국어 저지연·저전력 기준선          | 영어 전문용어, 띄어쓰기, 원거리 음성     |
| sherpa-onnx / SenseVoice int8               | 한국어·영어 혼용 구간 인식           | 문장 단위 지연, 한국어 강의 CER          |
| whisper.cpp / Whisper large-v3-turbo FP16 | 사용자 지정 기본 강의 모델 | 구간 경계 정확도, Metal 메모리·전력·속도 |
| Lightning-SimulWhisper                      | 스트리밍/ANE 설계 참고               | 비상업 라이선스, 독립 전력 벤치마크 부재 |

특정 모델을 아직 ‘강의에 가장 정확함’으로 추천하지 않는다. 모델 크기는
다운로드/디스크 크기이며 실행 메모리와 다르다. Parakeet 유럽 언어 모델,
영어·중국어 전용 모델은 한국어 기본 목록에 넣지 않는다.

## 작업 순서와 검증 관문

1. 기반: IPC 계약, 세션 저장/복구, 모델 설치, 네이티브 추론 격리.
2. 수직 통합: 마이크 → 디스크 → 실시간 한국어 인식 → 녹음 탭.
3. 학습 UX: 일시정지/재개, 다시 듣기, 중요 시간 표시, PDF/MD 연결,
   전사 검색, 마크다운 내보내기, 녹음 이력과 전역 녹음 표시.
4. 장애 테스트: 모델 다운로드 취소/손상, 디스크 쓰기 실패, 중복 청크,
   엔진 종료, 탭 이동, 절전, 오디오 장치 분리, 앱 강제 종료 후 복구.
5. 정확도 비교: 동의받은 실제 강의 데이터에 정답을 붙여 한국어 CER,
   영어 용어 오류, 숫자, 무음 환각, 자막 확정 지연을 측정.
6. 지속 성능: 2시간·4시간 실제 시간 구동, 메모리 추이, RTF, 누락,
   배터리와 온도/thermal-state를 함께 기록. 8/16GB Mac 및 Windows 비교.
7. 배포: 네이티브 바이너리 서명/패키징 검증, 오프라인 새 설치,
   권한 거절/재시도, 접근성·좁은 분할 화면·밝은/어두운 테마 점검.

7일을 사용할 경우 위 항목에 순서대로 집중하되, 시간 경과를 완료로
간주하지 않는다. 실제 시간 soak와 사람의 정확도 평가 전에는 장시간
성능·발열·최고 정확도를 검증 완료로 표시하지 않는다.

## 출시 목표 (미측정)

- Whisper 임시 자막 지연·확정 지연은 아래 실측과 별도로 실제 시간 입력에서 측정한다.
  Whisper는 네이티브 스트리밍 모델이 아니므로 1초 미만 지연을 보장하지 않는다.
- 4시간 녹음 시 오디오 청크 누락 0, 중복 확정 문장 0.
- 정상 구동에서 추론 RTF p95 < 0.7, 30분 이후 메모리 지속 증가 없음.
- 엔진 장애 후 원음 보존, 재시작 후 저장한 마지막 청크까지 복구.
- 실시간과 정밀 전사의 정확도를 분리 평가하고, 후처리가 원문을
  요약·의역하거나 학생의 기존 필기를 덮어쓰지 않도록 한다.

## 구현 및 검증 현황 — 2026-09-11

현재 상태는 **실제로 실행되는 첫 수직 통합 버전**이다. 전체 출시 관문을
통과한 완성품이나 한국어 강의 최고 정확도 엔진을 의미하지 않는다.

### 사용하기

1. `pnpm dev`로 앱 실행 → 과목 선택 → 새 탭 메뉴의 **녹음**.
2. 기본 선택인 **Whisper large-v3-turbo**(약 1.625 GB, VAD 포함)를 다운로드한다.
   FP16 모델이며 양자화된 다른 모델로 자동 대체하지 않는다. 다운로드 크기와
   실행 메모리는 다르다. Zipformer/SenseVoice는 선택 가능한 이전 엔진이다.
3. 마이크와 강의 제목을 선택하고 녹음을 시작한다. 강의 녹음 전 동의를
   확인한다. 탭 이동·닫기와 다른 과목으로의 이동에도 전역 녹음 표시가 남는다.
4. PDF/MD를 선택해 현재 시간과 연결한다. PDF는 페이지 번호를 지정할 수
   있다. 연결한 자료를 누르면 녹음 옆에 열리고, PDF는 지정 페이지로 이동한다.
5. 종료 후 시간 표시를 눌러 다시 듣거나, 선택한 모델로 자막을 다시 생성한다.
   마크다운 내보내기는 새 필기를 만들며 기존 필기를 덮어쓰지 않는다.

원음은 과목 폴더의 `녹음/<세션 ID>/audio.wav`에 저장한다. 16 kHz/16-bit/mono
기준 시간당 약 **115.2 MB**, 4시간 약 **460.8 MB**다. 세션 메타데이터,
자막, 시간 연결은 앱의 SQLite에 저장한다. 모델은 앱 userData 아래
`speech-models`에 저장하며 모델 다운로드와 STT 처리는 분리되어 있다.
STT 코드에서 음성이나 자막을 외부 서비스로 전송하지 않는다.

### 안전 장치

- AudioWorklet에서 0.5초 PCM 청크 수집 → 디스크 저장/fsync → 수신 확인.
  중복 청크는 재저장하지 않으며 순서 누락은 오류로 보고한다.
- 네이티브 추론은 별도 `Bandal Speech` utility process에서 CPU 2스레드로
  제한하며 Whisper는 Apple Silicon의 Metal GPU를 함께 사용한다.
  한 번에 한 청크만 보내고 밀린 음성은 디스크에서 읽는다.
- Whisper: 원음 연속 구간을 보관하고 VAD는 구간 경계의 참고로 쓴다.
  에너지가 있는 앞부분을 보존하되 VAD의 음성 근거 없이 Whisper를 호출하지
  않는다. 짧은 발화를 최소 약 12초 문맥으로 합치고 최대 28초에 확정한다.
  실제 강의에서 VAD가 처음 약 6초를 놓쳐 발생했던 도입부 누락을 수정했다.
  30초 고정 링 버퍼에서 약 4초부터 임시 자막을 만들고, 추론 소요 시간의
  4배 이상 간격으로 갱신해 불필요한 재분석을 줄인다. 이는 정확한 전력 제한이
  아니라 추론 빈도 제어다. 모델은 세션당 한 번 로드한다. 일시정지 시 마지막
  발화를 확정하며 재개 후에도 원음 샘플 시계를 유지한다.
- 재전사·종료 후 마무리·6초 이상 밀린 입력에서는 임시 자막 재분석을 생략하고
  확정 자막 처리에 집중한다. 고정 길이 창이라 긴 발화의 강제 경계에서는
  여전히 단어 누락/반복 가능성이 있으며 사람의 정답과 대조해야 한다.
- Node 바인딩의 타임스탬프는 **밀리초**다(whisper.cpp 원래 단위와 다름).
실제 음성 범위로 제한하고 확정 자막의 시간이 역행하지 않게 한다.
- Whisper의 순간적인 발화 디코딩 때문에 과부하 표시가 튀지 않도록
  UI의 처리 비율은 최근 최대 30초 입력의 소요 시간을 합산한다.
- Zipformer는 최대 15초마다 스트림을 교체한다. SenseVoice는 Silero VAD의
  512-sample 창과 최대 12초 발화 구간을 사용한다. UI는 자막 200개씩 조회한다.
- 엔진 장애 시 원음 수집은 유지하고, 종료 후 저장된 원음으로 재전사한다.
  입력·저장 장애는 ‘중단’으로 표시한다. 늦게 도착한 이전 세션의 저장 응답은
  새 녹음의 상태를 변경하지 않는다.
- 디스크 부족으로 중단 상태 저장까지 실패하더라도 엔진과 절전 억제를
  해제하고 UI에 알린다. 다음 실행에서 디스크의 원음과 이전 상태를 복구한다.
- macOS thermal-state가 serious이면 추론 사이에 250 ms 여유를 둔다.
  critical이면 추론만 미루고 원음은 계속 저장한다. 냉각 후 따라잡는다.
  이는 OS 상태 기반 부하 조절이며 발열 제거를 보증하지 않는다.
- 현재 Whisper macOS 네이티브 바이너리는 macOS 15 이상을 요구한다.
  arm64/x64의 Mach-O 최소 버전을 확인했으며 구버전에서는 다운로드/실행을
  설명과 함께 차단한다. 앱 전체의 최소 버전은 올리지 않는다.
- 녹음 중 백그라운드 타이머 제한을 해제하고 유휴 절전을 억제한다.
  강제 잠자기·창 종료·마이크 상실·15초 입력 끊김은 중단으로 남긴다.
- 활성 오디오의 내용 갱신은 자료 트리 재조회에서 제외한다. 파일 생성·삭제·
  이름 변경과 녹음 종료 때는 갱신해, 0.5초마다 과목 전체를 다시 읽지 않는다.
- 모델은 고정 리비전, 크기와 SHA-256으로 검증한다. 취소/실패한 임시
  다운로드를 제거하며, 로드 전 손상이 발견되면 재다운로드 UI를 표시한다.

### large-v3-turbo 실제 강의 검증

2026-09-11, Apple M4 / 16 GB / macOS 26.2. 사용자가 제공하고 녹음 동의를
확인한 한국어 전자기학 MP3를 macOS `afconvert`로 16 kHz mono PCM으로
변환했다. 원본은 수정하지 않았고 오디오를 외부에 전송하지 않았다.
개인 강의 파일·전사문은 저장소 밖에 보관한다. 정답 전사는 제공되지 않아
아래 수치는 CER/WER이나 정확도 순위를 의미하지 않는다.

| 경로 | 입력 길이 | 추론 소요 시간 (로드 제외) | RTF | 최대 프로세스 RSS |
| --- | --- | --- | --- | --- |
| 파일 전체 순차 전사 기준선 | 1,075.223초 | 58.268초 | 0.054 | 약 1.99 GiB |
| 실시간 엔진에 0.5초씩 입력, 임시 자막 포함 | 1,075.223초 | 288.709초 | 0.269 | 약 2.04 GiB |

기준선은 241개 구간, 실시간 경로는 228개 확정 구간 및 193회 임시 자막
갱신을 생성했다. 실시간 경로에서 가장 오래 걸린 한 입력 처리는 1.834초였다.
이는 마이크부터 화면까지의 p95 지연이나 최대 발열 수치가 아니다.
초기 Metal 셰이더 준비를 포함한 첫 로드 13.477초, 캐시가 있는 후속 로드
0.469초였다. 네이티브 로그에서 Apple M4의 MTL0 백엔드 사용을 확인했다.

도입부 누락과 시간 단위 변환 오류를 고쳤고, 마지막 음성 구간까지 처리,
시간 역행/원음 범위 초과 없음, 전사 후 60초 무음에서 자막 없음 등을 확인했다.
`A/B`, 수식, 일부 전공 용어 오인식은 남는다. 파일 기준선과 짧은 문맥을 쓰는
실시간 전사 결과는 다르므로 원음 대조 없이 정확한 필기로 취급하면 안 된다.

재현(명시적으로 준비한 로컬 모델 폴더와 16 kHz WAV 경로 필요):

```sh
node scripts/benchmark-whisper.mjs MODEL_BIN LECTURE_WAV OUTPUT_DIRECTORY
BANDAL_WHISPER_MODEL_DIR=MODEL_DIRECTORY BANDAL_WHISPER_WAV=LECTURE_WAV pnpm exec vitest run tests/main/recordings/whisper.integration.test.ts
BANDAL_WHISPER_MODEL_DIR=MODEL_DIRECTORY BANDAL_WHISPER_WAV=LECTURE_WAV BANDAL_WHISPER_REALTIME_SECONDS=180 pnpm exec playwright test -c e2e recording.spec.ts -g large-v3-turbo
```

추가로 macOS arm64 설치본에서 180초를 실제 시간 속도로 IPC에 재생했다.
창을 숨긴 상태에서 2,880,000개 샘플을 모두 저장·전사했고 35개 확정 구간을
생성했다. 추론 중 18회 측정한 엔진 working set은 1,715.86~1,759.34 MiB,
OS thermal-state는 모두 `nominal`이었다. 내보내기·재시작 복구도 통과했다.
이는 **3분 IPC 재생 테스트**이며 실제 마이크/4시간 지속성/배터리 소비 검증이 아니다.
최소화 요청이 실제로 적용되지 않았던 이전 시도는 백그라운드 실측에서 제외했다.

일반 테스트 3,113개와 녹음 E2E 5개가 통과했으며 타입 검사, 미사용 코드 검사,
빌드, macOS arm64 비서명 설치본 실행을 확인했다. 이 macOS Whisper 실행기는
Intel 실기기와 Windows에서 아직 검증하지 않았다.

### 이전 경량 엔진 기준선 (Whisper 성능이 아님)

환경: Apple M4, 16 GB, macOS arm64, sherpa-onnx-node 1.13.8.
공식 한국어 샘플 `test_wavs/0.wav`(3.5265초)와 2초 무음을 반복했다.
샘플의 대표성은 매우 제한적이며 CER/WER 평가 자료가 아니다.

| 모델                         |     모의 음성 길이 | 가속 처리 시간 | 전체 평균 RTF |
| ---------------------------- | -----------------: | -------------: | ------------: |
| Zipformer Korean int8        | 14,402초(약 4시간) |        468.3초 |        0.0325 |
| SenseVoice int8 (2024-07-17) | 14,402초(약 4시간) |        214.8초 |        0.0149 |

RTF는 계산 시간/음성 길이이며 1 미만이면 입력 속도보다 빠르다는 뜻이다.
위 수치는 반복 입력의 평균 처리량이다. 실제 자막 지연 p95, 배터리 소비,
발열 수치 또는 **4시간 실제 시간 녹음 결과가 아니다**. 테스트 프로세스의
RSS는 테스트 러너와 앞선 모델 할당을 포함하므로 모델별 메모리로 보고하지 않는다.

별도로 실제 Electron/AudioWorklet/네이티브 Zipformer 경로를 **5분 실제 시간**
구동했다. 창을 최소화한 상태에서 20초 간격으로 수집량 증가를 확인했다.
마지막 고정 패키지 실행(03:34 UTC 시작)의 주기적 조회에서 수집은
4,848,000 샘플, 추론은 4,840,000 샘플로 0.5초 분량 차이가 있었으며,
종료 후 나머지 처리를 마치고 저장 완료 상태에 도달했다.
이 구간의 음성 utility process working set은 약 196–277 MiB,
프로세스 시작 이후 peak working set은 약 345 MiB였다. 5분 관측만으로
장기 메모리 안정성을 단정하지 않는다. 온도·배터리·소비 전력은 측정하지 않았다.

2025년 SenseVoice 변환 모델도 비교했으나 이 한국어 샘플을 다른 언어로
인식하는 문제가 있어 현재 카탈로그는 검증한 2024-07-17 버전을 고정했다.
이 한 샘플만으로 두 버전의 전반적 정확도 우열을 판단하지 않는다.

자동 검증 범위: 원음/헤더 복구, 중복·누락·경로 이탈 방어, 자막 페이지 제한,
자료 이름 변경, 다운로드 손상·취소, 추론 지연/장애, 과열 상태 모의 주입,
마이크 상실, 녹음 세션 간 비동기 응답 격리, 밝은/어두운/좁은 화면,
실제 한국어 자막, pause/resume, 필기 분할 열기, 탭 이동, 내보내기와 재실행.
실제 네이티브 프로세스를 강제 종료해도 추가 원음이 저장되고 다른 모델로
재전사할 수 있는지도 별도 Electron 테스트로 확인했다. 두 모델에 1분 무음과
약 2분 연속 발화를 넣어 무음 중 자막 없음, 단조 증가하는 시간 범위,
긴 발화의 구간 분할도 확인했다.

배포용 unsigned `.app`에서도 네이티브 로드를 확인했다. Apple Silicon 앱과
Intel x64 앱의 UI/한국어 STT/재전사/엔진 강제 종료 복구/PDF 페이지 연결을
검사했다. x64 검사는 M4의 Rosetta에서 수행했으므로 실제 Intel 기기 성능
검증과 다르다. pnpm 9의 `supportedArchitectures`에 x64/arm64를 지정해
Mac 교차 패키징 때 대상 음성 바이너리가 누락되지 않도록 했다. Windows는
Windows 환경에서 별도 검증해야 한다. 코드 서명과 공증은 수행하지 않았다.

최종 확인: 일반 테스트 **3,104개 통과 / 10개 opt-in 등 건너뜀**, 타입 검사,
deadcode 검사, 프로덕션 빌드 통과. 최신 Apple Silicon 패키지의 E2E 4개와
고정 패키지의 5분 soak 포함 E2E 4개를 각각 통과했다. Intel 패키지도
Rosetta에서 E2E 4개를 통과했다. 실행 중 `out`을 재빌드했던 중간 검사는
필기 열기에서 실패해 최종 통과 판정에 사용하지 않았고, 이후 고정된
패키지 경로로 전체 흐름을 다시 검증했다.

### 재현 명령

일반 테스트는 모델 다운로드를 하지 않는다. 네이티브 벤치마크는 약 373 MB의
모델과 작은 공개 음성 샘플을 다운로드하는 명시적 opt-in이다.

```sh
pnpm typecheck
pnpm test
pnpm deadcode
pnpm build

BANDAL_STT_CACHE_DIR=$(mktemp -d /tmp/bandal-stt-benchmark.XXXXXX)
BANDAL_STT_BENCHMARK_DIR="$BANDAL_STT_CACHE_DIR" BANDAL_STT_STRESS_MINUTES=240 pnpm exec vitest run tests/main/recordings/stt.integration.test.ts
BANDAL_STT_BENCHMARK_DIR="$BANDAL_STT_CACHE_DIR" pnpm exec playwright test -c e2e e2e/recording.spec.ts
BANDAL_STT_BENCHMARK_DIR="$BANDAL_STT_CACHE_DIR" BANDAL_STT_SOAK_SECONDS=300 pnpm exec playwright test -c e2e e2e/recording.spec.ts -g 'real native'
```

`benchmark.json`과 `live-soak.json`은 지정한 모델 캐시 경로에 저장된다.
실제 마이크를 몰래 녹음하지 않으며 E2E는 공개 샘플을 가상 MediaStream으로
주입한다. 테스트용 과목/프로필은 격리한다. 패키징된 앱을 검사할 때는
`BANDAL_E2E_EXECUTABLE`을 해당 앱의 실행 파일 절대 경로로 설정할 수 있다.

### 다음 관문 / 아직 구현하지 않은 것

- 실제 한국어 강의 평가셋: 동의를 받은 원거리 음성, 잡음, 전공 용어,
  한국어/영어 혼용과 정답 전사. 현재 정확도 순위나 ‘최고 모델’ 주장은 불가.
- large-v3-turbo는 FP16 + Metal로 구현했다. 양자화 비교,
  CoreML/ANE/MLX 경로는 아직 구현하지 않았다.
- 2/4시간 실제 시간 구동과 장치별 온도·전력·배터리·메모리 측정.
  현재 실측은 M4/16 GB뿐이며 Intel Mac/8 GB/Windows는 미검증이다.
- 물리 마이크 분리, 권한 거절/허용, 느린 외장 디스크와 디스크 가득 참,
  전원 강제 차단을 실제 하드웨어에서도 검증해야 한다.
- 코드 서명/공증된 설치본의 새 기기 테스트, 모델별 배포 라이선스 고지 검토.
- 시스템 오디오/온라인 강의 소리 수집, 화자 분리, 전문용어 사전,
  자막 직접 편집, 전체 녹음 검색, 클라우드 API는 후속 범위다.

Lightning-SimulWhisper는 설계 참고로 조사했으며 코드를 복사하지 않았다.
저장소의 PolyForm Noncommercial 라이선스는 현재 프로젝트의 MIT 라이선스와
동일한 조건이 아니므로 배포 엔진에 직접 편입하지 않는다.
