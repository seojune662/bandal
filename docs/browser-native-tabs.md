# 브라우저 탭, 이미지 클립보드, PDF 확대 개선 (0.56.0)

브라우저 페이지는 main의 `nativeTabs.ts`가 `WebContentsView`로 소유한다.
렌더러의 `nativePageHandle.ts`는 화면 위치와 기존 브라우저 조작·로그인·선택·영상
브리지를 연결한다. IPC는 등록된 앱 창의 최상위 프레임과 해당 창 소유 탭만 받는다.

사이트가 만든 창은 `setWindowOpenHandler.createWindow`의 `options.webContents`를
그대로 받아 반달 탭으로 표시한다. URL을 다시 열어 POST, referrer, 이름 있는 창,
opener/postMessage 연결을 잃지 않도록 한다. Chromium이 페이지 생성을 미루는
background-tab 링크만 원래 referrer로 최초 탐색한다. v0.59.0부터는 방문한 페이지를
탭 이동 때문에 파괴하지 않으며, 복원한 미방문 탭만 지연 생성한다. 일반/시크릿 세션은 계속 분리한다.

다운로드는 요청 과목을 유지한다. 파일 전송이 끝난 뒤 빈 다운로드 탭만 닫으며,
`mainFrame.executeJavaScript`로 현재 문서를 검사한다. `webContents.executeJavaScript`는
문서 로드 완료를 기다리므로 문서를 만들지 않는 다운로드 탐색에서 멈출 수 있다.
겹치는 메뉴·대화상자 및 탭 드래그 동안에는 네이티브 페이지를 숨기고 마지막 캡처 화면을 표시한다.

HTTP 오류 문서는 그대로 표시하고 상태 코드를 안내한다. 진단에는 URL의
쿼리/프래그먼트, 콘솔 인수, 인증 요청 본문을 수집하지 않는다. 로그인 POST를
자동 재시도하지 않는다. 서버의 503 응답이나 서비스의 브라우저 허용 정책 자체를
이 변경으로 해결했다고 간주하지 않는다. 실제 개인 계정 인증은 자동 검사하지 않았다.

노트 이미지는 PNG 픽셀과 휴대 가능한 HTML을 OS 클립보드에 함께 쓴다.
같은 과목에 붙이면 원본 참조를 재사용하고 다른 과목에는 assets 파일을 만든다.
비동기 변환 중 클립보드가 바뀌면 이전 복사 결과를 쓰지 않는다. 자르기는 복사에
성공했고 원래 문서와 선택이 유지된 경우에만 삭제한다.

PDF는 배율에 따라 다시 마운트되는 react-pdf의 canvas/customRenderer 대신,
Page의 유지되는 자식에서 완성된 비트맵과 다음 렌더 버퍼를 교체한다.
휠 크기로 연속 배율을 계산하고 포인터 위치를 유지한다. 다음 래스터는 입력이
멈춘 후 150ms에 그리며, 취소된 렌더가 표시 중인 캔버스를 지우지 않는다.

검증: 브라우저 POST·opener·중첩 탭·일반/시크릿 세션·다운로드·검색·단축키,
이미지 키보드/우클릭 복사·OS 이미지 읽기·과목 간 붙여넣기·클립보드 경합,
PDF 연속 확대의 프레임별 픽셀 유지·포인터 위치·필기 기하·100회 과목 전환.
기능과 관계없는 자료 전체 스캔, 필기 툴바 기본 조작 등은 반복하지 않는다.
