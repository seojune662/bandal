# v0.95.4 — 마크다운 필기에서 Tab 키로 들여쓰기

마크다운(.md) 필기를 쓸 때 Tab 키를 눌러도 탭이 입력되지 않는다는 피드백을 반영했다.

## 바뀌는 점

- 일반 문단·제목·코드 블록에서 Tab을 누르면 커서 위치에 탭 문자가 들어간다. 이전에는 Tab 키가 편집기 밖으로 포커스를 옮겼다.
- Shift+Tab은 커서 바로 앞의 탭을 지운다. 지울 탭이 없어도 포커스는 편집기에 남는다.
- 목록 항목의 들여쓰기·내어쓰기와 표의 셀 이동은 이전과 같다. 더 들여쓸 수 없는 첫 목록 항목에서 Tab을 눌러도 항목 글자에 탭이 섞이지 않는다.
- 저장된 파일에서 문단 맨 앞의 탭은 들여쓴 코드로 바뀌지 않도록 `&#x9;`로 기록된다. 다시 열면 탭으로 보인다.

## 검증

- v0.95.1은 Windows 설치본 E2E에서 새 Tab 검사가 앞 검사의 노트 편집기까지 함께 선택해 실패했으므로 공개하지 않았다. v0.95.2는 검사 대상을 해당 노트로 한정했지만, 노트 자동 포커스가 클릭보다 늦어 커서가 줄 앞에 놓이면서 줄 끝을 가정한 기대값이 실패해 공개하지 않았다(탭 입력·포커스 유지·다음 입력 뒤 탭 유지는 Windows에서도 확인됐다). v0.95.3은 커서 위치와 무관하게 검사해 Windows 빌드·E2E가 통과했다. 하지만 GitHub가 `macos-14` 러너를 더 이상 지원하지 않아(`The configuration 'macos-14-arm64-us-default' is not supported`) macOS 빌드가 시작되지 못해 공개하지 않았다. v0.95.1·v0.95.2의 macOS 취소도 같은 원인이다. 앱 코드는 같고, v0.95.4는 릴리스 macOS 빌드를 `macos-15` 러너로 옮겼다.

- 원인은 두 가지였다. 목록·표 밖에서 Tab이 바인딩되지 않았고, 노트 편집기에 ProseMirror 필수 CSS `white-space: pre-wrap`이 빠져 입력한 탭이 다음 글자 입력 때 지워졌다.
- `noteTabKeymap` 단위 검사 5개를 추가했고 통과했다.
- E2E `noteToolbar` 스펙 2개가 로컬에서 통과했다.
- PR #43의 영향 범위 CI가 통과했다.
