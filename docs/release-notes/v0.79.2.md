# v0.79.2

- 탭 재배치·분할 변경·여러 영역 병합을 반복한 뒤에도 다른 과목으로 탭을 끌어 옮길 수 있도록 수정합니다.
- 마지막 탭을 닫거나 다른 과목으로 옮긴 뒤 빈 과목 화면에 로고·과목 이름·시작 버튼을 표시합니다. 기존 버전에서 저장된 빈 화면도 복원합니다.
- 브라우저 탭을 누르거나 끄는 동안 웹페이지가 자동으로 초점을 가져가지 않도록 수정합니다. 이동을 마친 현재 활성 페이지에만 초점을 전달합니다.

## 원인과 검증

Dockview는 탭 이동과 배치 복원 중 React 탭 내용을 유지하면서 바깥 탭 요소를 교체합니다. 기존 코드는 처음 요소에만 드래그·키보드 처리기를 등록해 다음 드래그의 과목 이동 데이터가 누락됐습니다. 같은 밀리초 안의 연속 배치 변경과 여러 비활성 탭을 포함한 그룹 병합에서도 재현했습니다. 이동과 복원이 끝나면 현재 탭 요소에 처리기를 다시 연결합니다.

마지막 탭을 비운 뒤 보존된 단일 영역을 분할 화면의 빈 영역으로 취급하던 조건도 수정했습니다. 실제 영역 수를 구독하고 해당 화면이 속한 과목의 이름과 시작 동작을 사용합니다.

비활성 브라우저 탭은 마우스를 누르는 순간 활성화됩니다. 이때 예약한 네이티브 페이지 초점이 드래그 시작과 경쟁했습니다. 누름 상태에서는 자동 초점만 보류하고 실제 드래그가 시작된 뒤 페이지 가림 처리를 적용합니다. 드래그·크기 조정·화면 가림 중에는 기다리고, 페이지 숨김·제거·앱 초점 이탈 시 예약을 취소합니다. 비동기 페이지 생성 완료 후에도 조건을 다시 검사합니다.

수정 전 실패를 확인한 실제 Dockview 회귀와 브라우저 자동 초점 회귀를 포함했습니다. 탭·과목 이동 관련 단위 검사 53개, 자동 초점 관련 검사 39개와 렌더러 타입 검사가 통과했습니다. 로컬 Electron에서는 기존 이동 흐름 20개 및 최종 초점 수정에 직접 연결된 10개 흐름을 검증했습니다. 네 과목 간 마지막 탭 왕복 8회, 매번 취소 후 재시도, 과목 행·캔버스 드롭, 편집기 동일성, 시작 화면 복원·재시작, 그룹 병합 후 비활성 탭 이동을 확인합니다.

Windows에는 같은 네이티브 드래그 시나리오를 3회씩 실행하는 수동 회귀 작업을 추가했습니다. 테스트 좌표는 사이드바 전환이 끝난 뒤 실제 탭 위치를 확인하고, 좁은 창의 과목 목록에서는 목적지 행 높이로 목록을 빠져나와 다른 행을 지나지 않도록 합니다.

v0.79.1은 패키지 검사 실패로 공개하지 않았습니다. 최종 배포는 v0.79.2로 진행하며 같은 커밋의 CI 결과를 재사용하고, macOS·Windows 패키지 E2E, macOS 서명·공증, 설치 파일 업로드 체크섬과 두 자동 업데이트 피드를 검증합니다. Windows 설치 파일은 기존과 같이 미서명입니다. 자동 검사는 임시 프로필과 테스트 자료를 사용하며 개인 계정 연결·실제 OS 권한 허용·기존 설치본의 업데이트 설치는 별도 확인 대상입니다.
