# v0.87.1 — 사이드바 여백과 브라우저 마우스 입력 수정

왼쪽 과목 사이드바에서 학교와 그 아래 내용을 약 44px 위로 올렸다. macOS 창 제어 버튼과 학교 선택 버튼이 겹치지 않도록 공간을 확보하며, 일반 창·전체화면과 Windows 배치를 함께 처리한다.

로그인된 ChatGPT의 Home 집 아이콘에 마우스를 올려도 사이드바가 열리지 않던 문제를 수정했다. 사이트 상단의 `app-region: drag`가 Electron에서 실제 창 드래그 영역으로 해석되어 마우스 입력을 가로채고 있었다. 웹페이지에 적용하는 입력 정책으로 해당 스타일을 초기화하며, 새로고침·탐색·새 탭과 팝업에서도 적용한다. 사이트가 나중에 추가한 요소나 inline `!important` 스타일에도 우선한다.

반달은 Electron의 Chromium 엔진을 사용하며 Chrome 제품 전체를 포크한 앱은 아니다. 이번 문제도 렌더링 엔진 차이보다 내장 창의 입력 처리에서 발생했다. 전체 Chrome 기능과의 동일성을 의미하지 않으며, 브라우저 코드 점검 범위와 남은 제품 차이는 [감사 기록](../audit-browser-2026-10-21.md)에 남겼다.

브라우저 추가 개선:

- HTTP 인증 아이디나 비밀번호가 문자 그대로 `cancel`일 때 취소로 처리되는 문제를 수정했다.
- HTTP 인증창·인증서 선택창·사이트 권한창이 실패하거나 취소되어도 요청을 끝내도록 보완했다.
- 입력 문제 진단에 화면 크기·배율·마우스 및 터치 지원 정보를 추가했다. 마우스 움직임이나 페이지 내용은 수집하지 않는다.

## 검증

- 실제 계정으로 로그인한 별도 반달 창에서 문제를 재현했다. 같은 세션에 원인 수정을 적용한 뒤 사용자가 실제 마우스로 **“이제 열림”**을 확인했다.
- 영구 수정이 포함된 개발 앱을 같은 테스트 프로필로 다시 실행했다. 임시 주입 스타일 없이 로그인된 Home 아이콘이 있는 문서에서 원인 영역의 계산값이 `none`임을 확인했으며 새로고침 뒤에도 유지됐다.
- 사이드바 위치·일반 창·전체화면 회귀 E2E 10개를 통과했다.
- 브라우저 호환성 E2E 23개를 통과했다. 실제 원인과 같은 드래그 헤더를 포함한 hover 회귀는 동적 스타일·주소 제안·툴팁·창 크기·iframe·탐색·새로고침·자식 탭을 확인했다. OS 실제 커서와 자동 입력 사이의 경합을 처리한 뒤 해당 검사 5회 모두 통과했다.
- 브라우저 감사 당시 서로 겹치지 않는 단위 검사 77개 파일·969개를 통과했다. 추가 입력 정책 및 연결의 직접 영향 검사 3개 파일·35개, 입력 진단 검사 13개도 통과했다. 이 수치는 실행별 결과이며 중복 검사를 합산한 총계가 아니다.
- main·renderer 타입 검사와 앱 빌드를 통과했다. 최종 설치 파일 E2E와 서명·공증·공개 여부는 아래 공개 결과에 기록한다.

자동 마우스 검사는 네이티브 OS hit test를 우회할 수 있으므로, 계산된 드래그 스타일 검사와 실제 사용자 마우스 확인을 구분한다. 전역 CSS가 Shadow DOM 내부까지 적용된다고 보장하지 않는다. 실제 OS 장치 권한 허용, 학교 SSO, TLS 인증서·개인 브라우저 자료 가져오기는 이번 실제 계정 확인 범위에 포함하지 않는다.
