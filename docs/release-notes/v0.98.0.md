# v0.98.0 — iPad 같은 설정창, 동기화 탭

설정창 사이드바를 iPad 앱처럼 짧은 구역 목록으로 바꾸고, 그동안 개발용 스위치 뒤에 숨어 있던 동기화 패널을 설정에 항상 보이게 했다. iCloud 동기화 코드를 다시 검토해 폴더가 비었을 때와 macOS가 접근을 막았을 때의 문제를 고쳤다. 계정 설정에서는 연결된 로그인 수단과 연결이 거절된 이유를 보여 준다.

## 바뀌는 점

- **설정 구역**: 사이드바를 일반, 화면, 계정, AI, 동기화, 통합, 플러그인, 개인정보·권한, 정보의 9개 구역으로 줄이고 그룹 제목을 없앴다. 구역을 누르면 관련 패널이 위아래로 이어서 보인다. 예를 들어 화면에는 테마·탭·위젯이, 계정에는 프로필·학교·과목이, AI에는 엔진 연결·화면 도우미·사용 통계가 들어 있다. 패널 이름은 그대로 두었다. 그래서 설정 검색, ⌘/, 앱 메뉴, 다른 화면의 "설정 열기" 링크는 해당 구역을 열고 그 패널까지 스크롤한다. 검색하는 동안에는 맞는 항목이 없는 패널을 숨긴다. iPad와 다른 데스크톱 전용 항목(달력·브라우저 가져오기·플러그인·기기 권한)은 그대로 두고 통합, 플러그인, 개인정보·권한 구역에 모았다.
- **동기화 탭**: 동기화 패널은 지금까지 `BANDAL_SYNC_UI` 환경 변수를 켠 개발 빌드에서만 보였다. 이제 설정 › 동기화에 항상 보인다. 빠른 파일 검색에서도 동기화 설정 행을 거르지 않는다. iCloud Drive 또는 Google Drive의 반달 폴더로 iPad와 과목·자료·필기·노트를 맞추며, 반달 계정 로그인과는 관계없다.
- **폴더가 비었을 때 멈춤**: 이전에는 동기화 중인 컴퓨터가 빈 반달 폴더를 보면 새 "처음 올림" 표시를 쓰고, 아직 보내지 않은 변경만 올렸다. 그래서 폴더를 비우거나 iPad에서 다시 만든 뒤에는 이 컴퓨터의 과목이 다시 올라가지 않았다. iCloud에서는 재시작 직후 Mac이 폴더 내용을 아직 받지 못한 상태에서 같은 일이 생겨, 이 표시가 iPad가 만든 폴더 위에 덮어써질 수 있었다. 이제는 iPad와 같은 방식으로 동작한다. 이 컴퓨터의 기기 파일이 폴더에 있다가 사라지면 동기화를 멈추고(설정에 "반달 폴더에서 이 컴퓨터의 기록이 사라져 멈췄어요") 파일이 다시 보이거나 사용자가 **다시 올리기**를 누를 때까지 기다린다. 다시 올리기는 확인을 거친 뒤, 보낸 기록을 지우고(과목 연결은 유지) 전체를 다시 훑어 모두 올린다.
- **빈 iCloud 폴더에 처음 연결할 때**: iCloud에 폴더 내용을 받아 오라고 요청하고(`brctl download`), iPad 자료가 아직 도착하지 않았을 수 있다고 안내한다. 내용이 보이면 **다시 확인**으로 이어 간다.
- **macOS가 iCloud 폴더를 막을 때**: 이전에는 macOS 개인정보 보호 설정이 반달의 iCloud Drive 접근을 막으면 원인 없는 실패로만 보였다. 이제 "시스템 설정 › 개인정보 보호 및 보안 › 파일 및 폴더"에서 허용하라고 안내한다. 아직 내려받지 않은 파일을 읽지 못하면 그 파일을 iCloud에 다시 요청한다.
- **iPad 도형 필기 보존**: iPad가 알아본 도형(직선·화살표·꺾은선·다각형·타원)의 정보(`data.shape`)를 데스크톱에서 읽고 다시 쓸 때도 유지한다. 이전에는 데스크톱이 이 정보를 버려서, 데스크톱을 거친 도형이 iPad에서 일반 필기로 보일 수 있었다. 잘못된 도형 정보는 버리지만 필기 자체는 남긴다.
- **로그인 수단 연결**: 계정 설정에서 이미 연결된 수단은 "Apple 연결됨"처럼 표시하고, 둘 다 연결됐으면 어느 쪽으로 로그인해도 같은 계정이라고 알려 준다. 연결이 거절되면 이유를 보여 준다. 이미 다른 반달 계정에 연결된 수단이면 그 계정으로 로그인하라고, 그 밖의 실패면 잠시 후 다시 시도하라고 안내한다. 이전에는 거절 이유를 보여 주지 않았다.

## 검증

- 단위 검사: `tests/shared/settingsCategories.test.ts`는 모든 패널이 정확히 한 구역에 들어가고, 패널 이름으로 그 패널을 담은 구역이 열리는지 확인한다. 설정 화면 검사(`settingsResponseOrder`, `autoProvider`)는 한 구역에 여러 패널이 함께 그려지는 구조에 맞춰 바꿨다.
- 단위 검사: `tests/main/sync/engine.test.ts`는 동기화한 적 있는 폴더가 비면 처음 올림 표시를 쓰지 않고 멈추는지, 다시 올리기가 표시와 기기 파일, 그리고 전체 자료를 다시 보내는지 확인한다. `icloud.test.ts`는 접근이 막힌 폴더(권한 000)에서 macOS 접근 안내가 나오는지, `adapter.test.ts`는 iPad 도형 정보가 가져오기·내보내기 뒤에도 남고 잘못된 정보만 버려지는지, `authLifecycle.test.ts`는 연결된 로그인 수단 목록과 거절 이유를 확인한다. 동기화 단위 검사 230개와 계정 검사를 합친 282개가 통과한다.
- 설치본 E2E가 고를 영향 스펙 18개(`accountNotes`, `appleCalendar`, `browserImport`, `recordingUx`, `settingsSearch`, `settingsShell`, `accountProfileBackup`, `pluginCenter`, `theme`, `sidebars`, `uiRedesign`, `tabDrag`, `favoritesDrag`, `materialsDrag`, `viewportMenus`, `pdfExport`, `coursePerformance`, `aiConnections`, 50개 검사)가 개발 빌드에서 통과한다. 설정 위치를 가리키던 스펙은 새 구역(예: 탭 → 화면, 달력·브라우저 → 통합, 학교 → 계정)으로 바꿨다.
- `recordingUx`는 이번 변경 전 `main`(`a46f1364`)에서도 3개가 실패했다. v0.95에서 자료 폴더가 제자리에서 펼쳐지게 바뀌고, v0.96에서 AI가 레일 옆 자리에 열리게 바뀐 뒤 검사를 갱신하지 않았기 때문이다(`상위 폴더로` 버튼과 `AI 닫기` 버튼을 찾았다). 이번 출시에서 이 스펙이 영향 범위에 들어오므로, 폴더는 녹음 행이 안 보일 때만 펼치고 AI는 레일 AI 버튼의 펼침 상태로 확인하도록 고쳤다.
- 타입 검사(`tsconfig.node.json`, `tsconfig.web.json`, `web-demo/tsconfig.json`), 대비 검사(`check-contrast`), `pnpm deadcode`가 통과한다.
- 개발 빌드에서 설정 › 동기화, 화면, 계정, 일반 구역을 스크린샷으로 확인했다. 동기화 구역 제목과 연결 묶음 제목이 둘 다 "동기화"로 겹쳐서, 연결 묶음 제목을 "저장소 연결"로 바꿨다. 개발 빌드에는 Google 클라이언트 값이 없어 iCloud만 보인다. 릴리스 빌드는 `MAIN_VITE_GMAIL_CLIENT_ID`가 비면 실패하므로 iCloud와 Google Drive가 둘 다 보인다.
