# v0.79.1

- 탭을 재배치하거나 분할 배치를 바꾸고 여러 탭 영역을 합친 뒤 다시 다른 과목으로 끌 때, 목적지 과목이 열리지 않던 문제를 수정합니다. 탭 표시 요소가 교체될 때 드래그와 키보드 처리를 새 요소에 다시 연결합니다.
- 마지막 탭을 닫거나 다른 과목으로 옮긴 뒤에도 빈 과목 화면에 로고·과목 이름·시작 버튼을 표시합니다. 기존 버전에서 저장된 빈 화면도 복원하며, 여러 영역으로 나눈 화면의 빈 영역은 그대로 유지합니다.
- 빈 화면의 이름과 새 탭 동작은 해당 화면이 속한 과목과 영역을 따릅니다.

## 원인과 검증

Dockview는 탭 이동과 배치 복원 중 React 탭 내용을 유지하면서 그 바깥의 탭 요소를 교체합니다. 기존 코드는 처음 요소에만 드래그·키보드 처리기를 등록해, 내용이 다시 렌더링되지 않는 이동에서는 다음 드래그의 과목 이동 데이터가 누락됐습니다. 같은 밀리초 안에 연속으로 배치를 바꿔도 이 문제가 재현됩니다. 이동과 배치 복원이 끝난 시점에 현재 탭 요소를 다시 연결하도록 수정합니다.

또한 마지막 탭을 비운 뒤 보존된 단일 영역을 분할 화면의 빈 영역으로 취급했습니다. 현재 영역 수를 구독해 단일 영역이면 과목 시작 화면을 표시하고, 분할 영역이면 각 영역 안내를 표시합니다.

단위 회귀는 실제 Dockview의 그룹 간 이동·같은 그룹 내 이동·여러 탭이 있는 그룹 병합·배치 복원·빠른 연속 배치 변경 뒤 드래그 데이터와 키보드 접근을 검사합니다. Electron 회귀는 네 과목 간 마지막 탭 왕복 8회, 매번 취소 후 재시도, 과목 행·캔버스 드롭, 편집기 유지, 로고·과목 이름 복원과 재시작을 검사합니다. 기존 분할 배치·과목 이동·브라우저·플러그인·채팅·녹음의 탭 이동 검사도 해당 범위에서 수행합니다.

로컬에서는 관련 단위 회귀 53개, 렌더러 타입 검사와 Electron 사용 흐름 20개가 통과했습니다. 실제 그룹 헤더 드래그로 병합한 뒤 비활성 탭을 다른 과목으로 옮기는 검사에서도 편집기 동일성과 표시를 확인했습니다.

CI는 영향받는 검사만 선택하고 릴리스는 같은 커밋의 성공한 결과를 재사용합니다. macOS·Windows 패키지 검사, macOS 서명·공증, 설치 파일 체크섬과 두 운영체제의 자동 업데이트 피드를 확인합니다. Windows 설치 파일은 기존과 같이 미서명입니다. 자동 검사는 임시 프로필과 테스트 자료를 사용하며, 사용자 개인 계정 연결·OS 권한 허용·실제 설치본의 업데이트 설치는 별도 확인 대상입니다.
