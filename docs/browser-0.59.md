# 브라우저·탭 개편 — v0.59.0

Electron·React·TypeScript, main 소유 WebContentsView와 Dockview를 유지한다. 렌더러의 `BrowserPageHandle`은 DOM 요소와 비동기 페이지 명령을 분리한다. 탭 이동은 페이지 ID를 유지하며 복제는 새 ID를 만든다. 복원한 미방문 페이지는 지연 생성하고 방문한 페이지는 탭 전환 때문에 파괴하지 않는다.

`pageClose.ts`가 beforeunload 결정을 처리하고 닫기·프로필 변경·창 종료가 같은 결과를 따른다. 창 종료 시 탭 배치를 보존하며 취소 시 이미 닫힌 페이지와 남아 있는 페이지를 구분한다. 취소 시 IPC 대기 타이머를 해제하고, 녹음·자료 감시·플러그인·함께하기의 정리는 실제 종료가 확정된 뒤 수행한다. 데이터베이스는 서비스 정리 이후 닫는다. 위치는 프레임당 한 번 계산하며 실제로 겹치는 메뉴와 모달만 페이지를 가린다. 탭 드래그·크기 조절은 공통 드래그 상태에 연결한다. 마지막 시크릿 페이지와 다운로드가 끝나면 저장소·캐시·인증 정보를 정리하고 정리가 끝날 때까지 새 시크릿 페이지 생성을 기다린다.

## 데이터 가져오기

| 원본 | 북마크·기록 | 쿠키 | 비밀번호 |
|---|---|---|---|
| Chrome·Edge / macOS | 프로필 직접 읽기 | 지원되는 일반 쿠키, Keychain 접근 허용 | Keychain 접근 허용 또는 CSV |
| Chrome·Edge / Windows | 프로필 직접 읽기 | 지원되는 DPAPI/AES 항목, 앱 바운드 암호화 제외 | 지원되는 OS 암호화 항목 또는 CSV |
| Firefox / macOS·Windows | 프로필 직접 읽기 | 일반 쿠키 | 공식 CSV 내보내기 |
| Safari / macOS | 공식 내보내기 ZIP | 내보내기에 없으므로 재로그인 | 공식 내보내기 ZIP 또는 CSV |

북마크 HTML과 비밀번호 CSV는 별도로 가져올 수 있다. Safari 구버전에서는 제공되는 파일 내보내기 경로만 사용한다. 비밀번호는 HTTPS 원본만 저장한다. 파티션·컨테이너 쿠키는 손실 없이 옮길 수 없어 지원 불가로 집계한다. domain/path, host-only, Secure, HttpOnly, SameSite, 세션·만료 의미를 유지한다.

원본은 수정하지 않는다. SQLite의 일관된 읽기 스냅샷을 사용하고 접근·잠금 실패를 표시한다. 기본 충돌 정책은 기존 정보 유지이며 교체를 따로 선택한다. 기록은 최근 90일·최대 2만 URL, 기존 CSV·HTML 파서는 최대 1만 항목을 처리한다. 재시도할 때 방문 횟수를 중복 가산하지 않는다. 북마크에는 대상 프로필을 저장하며 해당 프로필의 바로가기와 별표에 연결한다.

원본 경로와 비밀값은 main 안에 머문다. OS 도우미는 표준입출력 파이프를 사용하며 명령행·로그·평문 중간 파일에 비밀값을 쓰지 않는다. 렌더러에는 항목 수·지원 상태·결과만 보낸다. 기존 암호화 비밀번호 저장소는 계정 ID가 있는 v2로 변환하며 계정별 선택·수정·삭제를 지원한다.

## 성능 비교

macOS 26.2 arm64, Electron 43.4.1, 1440×900에서 각 버전을 별도 임시 프로필로 실행했다. 동일한 로컬 웹페이지 네 개를 사용해 실제 포인터 입력으로 100회 전환하고 활성 탭과 네이티브 페이지 표시를 확인했다. 입력 이벤트부터 두 번째 프레임까지 측정하며, 힙은 CDP로 GC한 뒤 읽는다. 드래그는 123회 dragover와 123~124개 렌더 프레임을 포함한다.

| 지표 | v0.58.0 | v0.59.0 |
|---|---:|---:|
| 탭 전환 P95 | 15.1ms | 14.6ms |
| 100회 전환 후 GC 힙 증가 | 0.473MiB | 0.452MiB |
| 전환 중 위치 IPC | 200회 | 200회 |
| 드래그 프레임 P95 | 8.7ms | 8.5ms |
| 드래그 중 위치 IPC | 10회 | 10회 |
| 앱 전체 working set | 1,063.94MiB | 1,155.41MiB |
| 살아 있는 웹페이지 | 4개 | 4개 |

단일 비교 실행의 수치이며 시작 시간·실제 인터넷 로그인 지연을 뜻하지 않는다. 전환과 힙 기준은 충족하지만 전반적인 속도 향상이나 메모리 절감을 주장하지 않는다. 6개 이상 방문 페이지를 유지하는 변경은 과거 강제 폐기 방식보다 메모리를 더 사용할 수 있다. [측정 원본](browser-0.59-performance.json)과 `e2e/browserPerformance.spec.ts`로 재현할 수 있다.

## 검증 범위

- 로그인 POST 팝업·opener·이름 있는 창·다운로드·뒤로/앞으로·탭 닫기·프로필 전환 취소·앱 종료 취소·재시작 복원.
- 6개를 넘는 방문 페이지와 과목 화면 캐시 밖 페이지의 입력·스크롤·WebContents ID 유지, 시크릿 정리와 프로필 자원 해제.
- 네 원본의 합성 프로필/내보내기, 읽기 스냅샷·권한 거부·암호화 실패·쿠키 속성·지원 불가 항목·취소·중복·충돌·계정 저장소 이전.
- 실제 가져오기 UI의 대상 프로필 분리·북마크 연결·반복 가져오기, 탭 재정렬·분할·합치기·취소·닫기 복원·키보드 포커스.
- 합성 Firefox 쿠키를 실제 Electron 세션에 저장해 host-only/domain, Secure, HttpOnly, SameSite, 세션·만료 시각과 대상 프로필 격리를 확인했다.
- 100회 과목 전환 P95 17.6ms, GC 힙 증가 0MiB. 50개 탭 복원 시 선택한 필기 하나만 읽는 기존 조건도 통과했다.

실제 개인 계정 로그인, 사용자의 OS Keychain 접근 허용, 모든 사이트의 정책·DRM·확장 호환성은 자동 검증하지 않았다. Windows 설치 파일은 기존 배포 정책에 따라 미서명이며 macOS 앱과 도우미는 함께 서명·공증한다.
