# Apple 캘린더

v0.51.0부터 macOS 앱에서 Mac의 캘린더 앱에 등록된 iCloud·로컬·구독 캘린더를 함께 볼 수 있습니다. 별도 Google OAuth 연결은 추가하지 않습니다.

## 연결하기

1. **설정 → 달력 → Apple 캘린더 연결**을 누릅니다. 학업 보드의 **달력 → ··· → 달력 설정 · Apple 캘린더**에서도 같은 설정을 엽니다.
2. macOS의 캘린더 접근 요청을 허용합니다. macOS 14 이상에서는 전체 접근, macOS 12–13에서는 기존 캘린더 접근을 요청합니다. 설정을 열기만 해서는 권한을 요청하지 않습니다.
3. 표시할 캘린더를 선택합니다. 읽기 전용·구독 일정도 표시할 수 있으며 모두 해제하면 외부 일정이 숨겨집니다.
4. 과제를 보낼 기본 캘린더를 고릅니다. 쓰기 가능한 캘린더만 선택할 수 있습니다.

권한을 거절했다면 설정 안의 **시스템 설정 열기**에서 개인정보 보호 및 보안 → 캘린더의 접근을 허용합니다. Mac의 캘린더 앱에서 계정을 추가한 후 **캘린더 목록 새로고침**으로 다시 불러옵니다.

## 일정 보기와 보내기

달력에서 반달 과제와 Apple 일정을 함께 봅니다. 캘린더 색상·이름으로 출처를 구별하고 외부 일정을 누르면 시간과 장소를 확인합니다. 외부 일정 편집은 Apple 캘린더 앱에서 합니다. 다른 앱에서 변경한 내용은 반달을 다시 활성화하거나 달력의 새로고침을 누르면 반영되며, 열린 달력도 1분마다 갱신합니다.

기존 반달 과제를 열어 **저장하고 Apple 캘린더로 보내기**를 누르면 현재 편집 내용을 먼저 저장한 뒤 전송합니다. 다시 보내면 같은 일정을 갱신합니다. 날짜만 지정하면 하루 종일, 시간을 지정하면 해당 시각부터 1시간으로 저장됩니다. 두 앱의 변경 내용이 자동으로 양방향 동기화되는 방식은 아닙니다.

반달 과제 삭제나 연결 해제는 Apple 캘린더에 이미 보낸 일정을 삭제하지 않습니다. Apple에서 반복 일정으로 바꾼 항목은 해당 앱에서 수정합니다.

## 저장·구현·검증 범위

- macOS EventKit을 호출하는 Swift 도구를 앱 안에 포함합니다. 실행은 비동기 별도 프로세스에서 처리해 메인 창을 막지 않습니다.
- `userData/apple-calendar.json`에는 연결 여부, 선택한 캘린더 ID, 전송한 이벤트 ID만 보관합니다. 불러온 외부 일정의 내용은 반달 서버에 전송하거나 별도 파일로 저장하지 않습니다. 연결된 iCloud 계정 자체의 동기화는 macOS가 처리합니다.
- 연결 해제는 반달에서의 조회를 중단합니다. macOS 접근 권한 해제는 시스템 설정에서 관리합니다.
- 단위 검사는 권한 거부·해제, 읽기 전용, 빈 선택, 삭제된 캘린더, 중복 전송, 저장 실패, 날짜 경계와 중복 표시를 다룹니다. Electron E2E는 격리 프로필과 캘린더 응답으로 설정 진입·선택·해제·과제 편집 후 전송을 확인합니다.
- 개인 캘린더에 대한 실제 허용·전송은 자동 검사에서 수행하지 않습니다. 배포 앱에서 사용자가 연결 버튼을 눌러 macOS 권한을 허용해야 합니다.
