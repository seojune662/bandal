# 시작과 과목 전환

v0.54.0은 창과 입력 응답을 파일 준비 시간에서 분리한다.

## 실행 순서

1. `bandal-media` 프로토콜을 먼저 등록하고 기본 창을 만든다. Chromium은 렌더러 생성 당시 프로토콜 등록 상태를 사용하므로 이 순서를 유지해야 한다.
2. utility process에서 DB 마이그레이션과 중단된 녹음 복구를 마친 뒤 연결을 닫는다. 메인은 준비된 DB를 열고 서비스를 등록한다. preload는 그동안 들어온 IPC 요청을 대기시킨다. 실패는 기존 복구 안내로 연결한다.
3. 과목 메타데이터와 저장된 탭 배치를 복원한다. 폴더 접근 가능 여부는 비동기로 확인한다. 저장된 자료 목록을 먼저 표시한 뒤 실제 폴더와 대조한다.
4. 선택된 탭을 준비한다. 분할 화면의 보이는 탭도 포함한다. 숨은 탭은 자료 조회·뷰어 모듈 로딩을 시작하지 않는다. PDF의 보조 텍스트 추출은 첫 페이지가 그려진 뒤 시작한다.
5. 자료 목록·검색 색인은 배경에서 갱신한다. 에이전트의 검색은 별도 프로세스에서 최신 내용을 확인한 뒤 응답한다.

## 수명과 캐시

- 현재 과목을 포함해 최근 3개의 Dockview를 유지한다. DOM 순서는 고정하고 숨은 작업 공간의 크기를 유지해 PDF 캔버스와 스크롤이 사라지지 않게 한다. 숨은 화면의 입력과 브라우저 표시, PDF 교차 관찰·텍스트 추출은 중지한다.
- 오래된 과목을 해제하기 전 열린 필기를 저장한다. 저장 충돌/오류가 있거나 브라우저 에이전트가 실행 중이면 해당 과목은 보관한다. 이 경우 한도는 일시적으로 늘어날 수 있다. 녹음·채팅·다운로드 작업은 기존 서비스에서 계속 관리한다.
- 렌더러의 과목별 자료 목록 캐시는 폴더 경로까지 구분한다. 메인 캐시는 과목 ID·폴더 경로에 맞는 트리만 반환한다. SQLite의 `material_tree_snapshots`는 파생 캐시이며 사용자 원본이 아니다.
- 최근 3개 과목은 파일 감시를 유지한다. 파일 변경과 저장소 변경은 캐시 세대를 올린다. 이전 세대의 탐색 결과는 적용하지 않는다. 탐색 실패·상한 도달을 전체 파일 삭제로 해석하지 않는다.
- 탐색은 별도 프로세스에서 파일 정보 조회를 최대 4개씩 수행한다. 메인 색인 쓰기는 변경분만 최대 100개씩 적용하고 이벤트 루프에 제어권을 돌려준다. 전경 문서 읽기는 2개, 탐색·색인 배경 작업은 1개씩 실행한다. 작업 프로세스 오류나 60초 타임아웃은 요청을 거절하며 다음 시도에서 새 프로세스를 만든다.
- 검색 색인도 최대 100개 문서씩 트랜잭션을 나누고 사이에 DB 쓰기 잠금을 해제한다. 긴 본문은 더 작은 묶음으로 처리해 전경의 필기·설정 저장이 전체 색인 완료를 기다리지 않게 한다.
- 펼친 자료 행이 200개를 넘으면 주변 행만 렌더링한다. 키보드의 위/아래/Home/End 이동은 전체 목록을 기준으로 처리한다.

## 측정과 회귀 검사

`BANDAL_PERF_TRACE=1`은 메인 프로세스의 `globalThis.__bandalPerformance`에 창 생성·렌더러 로드·DB 준비·서비스 준비 시각, 채널별 IPC 횟수와 소요 시간을 기록한다. 요청 인수, 파일명, 문서 내용은 기록하지 않는다. 기본 실행에서는 비활성화된다.

2026-09-28, Apple M4 / RAM 16GB, 로컬 SSD, 임시 프로필에서 측정했다. 사용자 실제 자료·외장 드라이브·네트워크 볼륨 전체를 대표하는 수치는 아니다.

| 시나리오 | 변경 전 | 변경 후 |
|---|---:|---:|
| 파일 1만 개 최초 탐색 중 메인 루프 최대 지연 | 71.3ms | 4.3ms |
| 파일 1만 개 목록 준비 전체 시간 | 90.9ms | 199.4ms |
| 저장된 목록 스냅샷 응답 | — | 10.3ms |
| 최근 과목 100회 왕복, 두 프레임까지 P95 | — | 25.0ms |

전체 탐색은 비동기 분리와 양보 때문에 시간이 더 걸릴 수 있다. 그동안 창·입력은 계속 처리하며, 과목 복귀는 이미 준비된 화면을 재사용한다. 캐시 없는 큰 파일이 물리적으로 즉시 해석된다는 뜻은 아니다.

`e2e/coursePerformance.spec.ts`는 1만 파일 탐색 중 메인 루프 지연, PDF 캔버스를 유지하는 과목 100회 왕복, GC 후 힙 증가 한도, 3개 과목 보관, 탭 50개 복원 시 선택된 필기만 읽기, 긴 목록의 키보드 탐색을 검사한다. 릴리스에서도 macOS·Windows 패키지를 사용해 같은 검사를 실행한다.

자료 저장소 단위 검사는 탐색 도중 무효화, 실패 시 기존 스냅샷 보존, 폴더 재연결, 비동기 경로 이탈 검증을 포함한다. 작업 공간 검사는 이전 요청의 뒤늦은 응답과 복원 중 사용자 파일 열기를 포함한다. 기존 DB와 탭 배치 형식은 유지한다.
