# Bandal STYLEGUIDE

> UI 규약의 단일 기준 문서. 코드가 아니라 이 문서가 먼저다 — 새 표면을
> 만들기 전에 여기서 역할(role)을 고르고, 여기 없는 색·간격·모션을 쓰고
> 싶다면 먼저 이 문서와 `src/renderer/src/styles/`에 토큰을 추가한다.
> (Orca `docs/STYLEGUIDE.md` 패턴 — docs/orca-analysis.md §7)

핵심 태도: **chrome은 물러나고, 색은 상태를 말할 때만 쓴다.**
표면(배경·테두리·타이포)은 조용하게, 액센트는 "지금 여기"를 가리킬 때만
켠다. 기본 테마의 액센트는 문골드지만 테마·계열마다 다르다(§1.3·§1.4) — 코드는
`--accent`만 알면 되고, 어떤 색인지는 테마가 정한다.

---

## 1. 토큰 구조

- `styles/tokens.css` — 테마 독립 스케일 토큰(반지름·간격·타이포·모션·치수)
  과 시맨틱 컬러 토큰의 **목록 정의**. 맨 위에서 `themes/index.css`를
  `@import`하므로 엔트리(`main.tsx` / `settings-main.tsx`)는 이 파일만 알면 된다.
- `styles/themes/<id>.css` — **테마 하나 = 파일 하나.** 그 안에 토큰 대입
  블록(`:root[data-theme='<id>']`)만 있고 컴포넌트 규칙은 없다.
- `src/shared/theme.ts` — **테마 레지스트리.** 어떤 테마가 존재하는지 아는
  유일한 곳(이름·설명·light/dark 계열·창 배경색).
- 규칙: **컴포넌트 CSS에는 raw 색상값 금지.** 토큰만 사용한다. 테마가
  6개든 20개든 토큰만 지키면 공짜로 따라온다.

### 1.1 테마 추가하기 (2단계)

1. `styles/themes/<id>.css`를 만들고 `themes/index.css`에 `@import` 한 줄 추가.
   토큰 블록(`:root[data-theme='<id>'] { … }`) 하나에 필수 토큰 전부.
2. `src/shared/theme.ts`의 `THEMES`에 항목 하나 추가
   (`id·name·description·base·windowBackground`).
3. 계열마다 피커용 스와치 한 세트 —
   `styles/palettes/<palette>.css`에 `--swatch-<palette>-<id>-{bg,surface,text,accent}`.
   계열이 이 모드의 표면까지 다시 재단한다면 오버라이드 블록도 함께(§1.3).

그 외에는 **아무 코드도 고치지 않는다.** 설정 픽커·설정 검증·창 배경색은
전부 레지스트리에서 읽는다. `tests/main/theme.test.ts`가 이 계약을 검사한다
(토큰 누락, 레지스트리/CSS 불일치, `color-scheme` 불일치, 스와치 누락).

`windowBackground`는 그 테마의 `--bg-app`을 sRGB hex로 **정확히** 옮긴 값이다.
메인 프로세스가 CSS 로드 전에 창을 이 색으로 칠하므로, 어긋나면 실행 순간
다른 색이 번쩍인다.

### 1.2 대비 계약 (측정값, 눈대중 금지)

새 테마·새 계열은 다음을 **전부** 만족해야 한다. 눈대중 금지 —
`node scripts/check-contrast.mjs`가 모드 파일과 계열 파일을 읽어 **(계열 ×
모드) 조합마다** 브라우저와 같은 순서로 캐스케이드를 합성한 뒤 전부 계산해서
출력한다(oklch → sRGB → WCAG 상대휘도, 알파 토큰은 배경 위에 합성 후 계산).
sRGB 색역 이탈, 레지스트리 불일치, 피커 스와치 드리프트도 같이 잡는다.
실패가 있으면 exit 1이다. 조합 하나만 보려면 `ink:dark`처럼 인자를 준다.

### 1.3 두 축 — 모드 × 계열

화면은 축이 둘이다(`src/shared/theme.ts`).

- **모드**(`data-theme`) — 밝기와 표면. 표면 사다리, 텍스트 램프, 보더,
  그림자, 그리고 **모든 콘텐츠 색**(`--course-*` · `--highlight-*` ·
  `--status-*` · `--danger*`)을 가진다. `styles/themes/<id>.css` 한 파일.
- **계열**(`data-palette`) — 색 가족. 액센트를 모든 모드에서 갈아끼우고,
  자기가 다시 재단하는 모드에서는 표면·텍스트·보더·그림자 색조까지 덮는다.
  `styles/palettes/<id>.css` 한 파일.

`<html>`은 둘 다 달고 다닌다: `data-theme='dark' data-palette='moss'`.
계열 블록은 `:root[data-palette][data-theme]`이라 명시도에서 모드 블록을
이기므로, 계열은 자기가 실제로 바꾸는 토큰만 적으면 된다.

**콘텐츠 색은 계열이 건드리지 않는다.** `--course-초록`으로 표시한 과목은
어떤 계열에서도 초록이어야 한다 — 계열을 바꿨다고 과목 색이 따라 움직이면
그건 색이 아니라 정체성이 흔들리는 것이다. `tests/main/theme.test.ts`가
계열 파일에서 이 토큰들이 나오면 실패시킨다.

세 모드(`세피아`·`고대비`·`흑연`)는 표면이 계열과 무관하게 고정이다 — 각각
종이·최대대비·무채라는 목적이 색 가족보다 앞서기 때문이다. 이 모드에서 계열은
액센트만 바꾼다. 예외는 흑묵 세피아 하나로, 더 회색인 종이(`#ece6d8`)를 따로
쓴다.

| id | 이름 | 액센트 성격 | 표면을 다시 재단하는 모드 |
|---|---|---|---|
| `bandal` | 반달 | 문골드 — 반달 정체성 | (기준. 모드 파일이 곧 반달 값) |
| `ink` | 흑묵 | 채도를 낮춘 금빛 하나 | 다크 · 라이트 · 자정 · **세피아** |
| `lavender` | 라벤더 | 라벤더 — 따뜻한 기준점 없는 한색 | 다크 · 라이트 · 자정 |
| `moss` | 이끼 | 세이지 — 눈이 가장 덜 조절하는 색 | 다크 · 라이트 · 자정 |

계열을 추가하는 법: `styles/palettes/<id>.css` 한 파일(모드별 오버라이드 +
피커용 `--swatch-<id>-<mode>-*` 24개), `palettes/index.css`에 `@import` 한 줄,
`PALETTES`에 엔트리 하나. 그리고 `node scripts/check-contrast.mjs`.

### 1.4 모드 목록

액센트 설명은 기준 계열인 **반달** 기준이다. 다른 계열에서는 액센트만 그
계열의 색으로 바뀌고, 모드가 존재하는 이유(종이·최대대비·무채·OLED)는 그대로다.

| id | 이름 | base | 언제 쓰나 | 반달 계열에서 액센트가 말하는 것 |
|---|---|---|---|---|
| `dark` | 다크 | dark | 기본값. 대부분의 작업 | 문골드 = 반달 정체성 |
| `light` | 라이트 | light | 밝은 강의실, 낮 | 청동빛 앰버 (골드를 AA까지 낮춘 값) |
| `midnight` | 자정 | dark | 불 끈 방의 야간 학습, OLED 배터리 | 한 단계 어둡힌 골드 — 눈부심 억제 |
| `sepia` | 세피아 | light | PDF를 몇 시간 읽는 날 | 만년필 잉크 블루 — 따뜻한 종이 위 유일한 한색 |
| `high-contrast` | 고대비 | light | 저시력, 강한 조명, 빔프로젝터 | 딥 시그널 블루 — 흰 바탕에서 AAA 도달 |
| `graphite` | 흑연 | dark | 자료의 색만 보고 싶을 때 | 콜드 시안 — UI에서 유일한 유채색 |

모드 6 × 계열 4 = **24개 조합**. 설정 > 화면은 이걸 24칸 그리드로 늘어놓지
않고 축을 두 줄로 나눠 보여준다(계열 4칸, 모드 7칸). 카드는 언제나 *지금 고른
다른 축* 기준으로 실제 색을 미리 보여준다.

## 2. 표면 사다리 (elevation ladder)

`--bg-app → --bg-surface → --bg-raised → --bg-overlay` — 딱 4단.

| 토큰 | 역할 | 실제 사용처 |
|---|---|---|
| `--bg-app` | 바닥. 콘텐츠가 놓이는 캔버스 | 워크스페이스 중앙, 탭 본문, 검색 인풋 배경 |
| `--bg-surface` | 구조 chrome | 타이틀바, 사이드 레일, 카드(게이트 카드, 온보딩 카드) |
| `--bg-raised` | 표면 위 인터랙션 | hover 배경, 배지, 코드 조각, 보조 버튼 |
| `--bg-overlay` | 떠 있는 레이어 (반투명 + blur) | "+" 메뉴, ⌘P 검색, 컨텍스트 메뉴 |

안티롤:
- 사다리를 건너뛰지 않는다 (`--bg-app` 위에 바로 `--bg-overlay` 카드 금지 —
  떠 있는 것만 overlay).
- overlay에는 `backdrop-filter: blur(var(--space-3))`와
  `--border-strong`을 함께 쓴다.
- 모달 뒤는 항상 `--backdrop`.

## 3. 컬러 역할표 (roles / anti-roles)

| 토큰 | 역할 | 안티롤 (하지 말 것) |
|---|---|---|
| `--accent` (테마의 액센트) | **상태 강조·활성 표시에만**: 활성 탭 언더라인, focus ring, `aria-pressed`, primary 버튼, 스트리밍 커서, 반달 마크 | **대면적 배경 금지.** 본문 텍스트 색 금지. 장식용 그러데이션 남용 금지 |
| `--accent-muted` | 액센트의 면(面) 버전: 선택 배경, 사용자 채팅 버블, 안내 배너, focus glow | 텍스트 색으로 금지 (대비 부족) |
| `--on-accent` | 액센트로 채운 면 위의 라벨 (primary 버튼 글자, 체크 배지) | 액센트가 아닌 배경 위에 쓰지 않는다 |
| `--on-danger` | `--danger`로 채운 면 위의 라벨 (삭제 확정 버튼) | 위와 같다 |
| `--danger` | **파괴적 확정에만**: 삭제 확정 버튼, 오류 텍스트, 마감 지남 배지 | 취소(Cancel) 버튼 금지. "중요하니까 빨갛게" 금지. 경고성 안내는 `--accent-muted` 배너 |
| `--danger-muted` | 오류 배너/토스트 배경 | 성공·중립 상태 금지 |
| `--text-primary` | 제목, 본문 강조, 활성 항목 | — |
| `--text-secondary` | 본문, 설명 | — |
| `--text-muted` | 힌트, eyebrow, 비활성, 메타데이터 | 본문 전체를 muted로 깔지 않는다 |
| `--border-subtle` | 기본 구분선·카드 테두리 | — |
| `--border-strong` | 떠 있는 레이어 테두리, 보조 버튼 테두리, 스크롤바 | 일반 카드에 남용 금지 (시끄러워진다) |
| `--course-*` (6색) | 과목 정체성 전용: 과목 점, 보드 태스크 태그, 색상 스와치 | 과목과 무관한 장식 금지 |
| `--highlight-*` (4색) | PDF 하이라이트 전용 | UI 상태 표현 금지 |
| `--status-todo/progress/done` | 보드 컬럼 상태 + 준비 상태 점(예: 프리플라이트 OK) | 일반 텍스트 강조 금지 |

## 4. 반지름·간격·타이포

- 반지름: `--radius-sm`(6) 컨트롤 → `--radius-md`(10) 카드/메뉴 →
  `--radius-lg`(16) 큰 카드/다이얼로그 → `--radius-pill` 알약·원.
  임의의 px 반지름 금지.
- 간격: 4px 스케일 `--space-1..8`만 사용. 매직 넘버 여백 금지.
- 타이포: `--text-xs`(11) 메타/eyebrow → `--text-sm`(13) UI 기본 →
  `--text-base`(15) 본문 → `--text-lg`(18) 카드 제목 → `--text-xl`(24)
  화면 제목. 폰트는 `--font-sans`(Pretendard 계열)와 `--font-mono` 둘뿐.
- eyebrow 패턴: `--font-mono` + `--text-xs` + `--tracking-wide` + 대문자
  (`LIBRARY`, `MATERIALS`, `SETUP` …). 화면당 1개면 충분하다.

## 5. 모션

- **transform / opacity만 애니메이션한다.** width·height·margin 등
  레이아웃 속성 애니메이션 금지.
- 지속시간은 두 개뿐: `--dur-fast`(120ms) 마이크로 인터랙션(hover, press),
  `--dur-base`(200ms) 등장/전환. 이징은 `--ease-out`.
- 등장 모션 표준형: `opacity 0→1` + `translateY(6~8px)→0`
  (`chat-rise`, `onboarding-rise`, `preflight-drop` 계열).
- press 피드백: `transform: translateY(1px)` 또는 `scale(0.9±)`.
- 무한 반복 애니메이션은 "생각 중/불러오는 중" 같은 진행 상태에만
  (달 breathe, 점 pulse). 장식용 무한 루프 금지.
- `prefers-reduced-motion`은 base.css가 전역에서 죽인다 — 개별 컴포넌트에서
  신경 쓸 필요 없게 유지할 것.

## 6. 반달 마크

개념: **반달(半月) = 반(半) = 절반까지 찬 원.** 원 전체가 한 학기이고,
찬 절반이 지금까지 한 공부다. 그래서 마크는 "금빛 반원 + 나머지를 잇는
가는 링"이며, 흔한 초승달/보름달 아이콘과 구분되는 지점도 여기다.

- **브랜드 마크는 `components/BandalMark.tsx` 하나로 그린다** — 앱 아이콘
  (`scripts/generate-icon.mjs`)과 같은 지오메트리(기울기 -14°, 반지름의 15%만큼
  안쪽으로 부푼 명암 경계)를 공유하므로 아이콘과 앱이 같은 마크로 읽힌다.
  색은 `currentColor`만 쓰고, 호출부가 `color: var(--accent)`로 역할을 준다.
- **장식용 문장(emblem)·로딩 문**은 지금처럼 토큰 기반 CSS 원으로 그려도 된다:
  `linear-gradient(to right, var(--accent) 50%, var(--bg-raised) 50%)`
  + `--radius-pill`. 작고 반복되는 자리에는 이쪽이 싸다.
- 비트맵/일러스트 자산 금지 — 정체성은 토큰과 벡터로 표현한다.
  (`resources/icon.*`는 앱 번들 아이콘 전용이며 UI에서 불러오지 않는다.)

### 아이콘 크기 단계

16px 메뉴바/파비콘에서는 크레이터(1024 그리드 33px → 0.5px)와 별이 형태가
아니라 얼룩으로 읽힌다. 그래서 래스터 크기별로 디테일을 끊는다:

| 래스터 | 단계 | 달 반지름 | 빼는 것 |
|---|---|---|---|
| ≤ 32px | minimal | 268 | 별·크레이터·글로우·내부 음영 |
| 33–64px | medium | 252 | 별·크레이터 |
| 65–128px | detailed | 240 | 별 |
| ≥ 256px | full | 236 | — |

타일이 작아질수록 마크는 커진다(236 → 268). 메뉴바 크기에서의 광학 보정이다.

## 7. 빈 상태 (empty states)

구조 표준형: **문장(emblem) → 한 줄 사실 → 한 줄 안내 (→ 행동 버튼 하나)**.

톤 규칙 — *건조하지 않게, 그러나 절제되게*:
- 앱 본체(사이드바·워크스페이스·채팅·보드·검색)의 빈 상태와 힌트는
  **해요체**로 끝낸다. 감탄사·이모지·과장 금지. 한 문장 사실 + 한 문장
  안내면 충분하다.
- 설정 창의 설명문·오류문은 **합니다체**를 유지한다 (도구 창의 문서적 톤).
- 오류/실패 문구는 "~하지 못했습니다." + 다음 행동(다시 시도) 제시.

표준 문구 (그대로 재사용할 것):

| 표면 | 문구 |
|---|---|
| 과목 없음 (레일) | "첫 과목을 만들어보세요" / "자료와 노트를 과목별로 한곳에 모아보세요." |
| 과목 검색 0건 | "일치하는 과목이 없어요" + [검색 지우기] |
| 과목 미선택 (워터마크) | "오늘의 공부를 시작해볼까요?" / "왼쪽에서 과목을 고르면 그 과목의 작업 공간이 열려요." |
| 자료 없음 | "아직 자료가 없어요" / "Finder에서 파일을 끌어다 놓으면 PDF, 노트, 이미지가 한곳에 정리돼요." |
| 자료 검색 0건 | "일치하는 자료가 없어요" + [전체 자료 보기] |
| ⌘P 검색 0건 | "일치하는 자료가 없어요. 다른 이름으로 시도해보세요." |
| "+" 메뉴 0건 | "일치하는 항목이 없어요" |
| 채팅 첫 화면 | "이 과목에 대해 무엇이든 물어보세요" / "강의자료를 읽고 필기도 도와줘요." + 스타터 칩 3개 |
| 보드 전체 0건 | "다가오는 일정을 한눈에 정리해보세요" / "각 컬럼의 + 버튼으로 첫 과제나 시험을 추가할 수 있어요." |
| 보드 컬럼 0건 | "할 일을 추가해보세요" · "진행 중인 태스크가 없어요" · "완료한 태스크가 없어요" |

## 8. 상호작용 상태

- 모든 클릭 가능한 것은 hover / focus-visible / active 세 상태를 가진다.
  focus는 base.css 전역 규칙(`outline: 2px solid var(--accent)`)에 맡기고
  개별 outline을 덮어쓰지 않는다.
- hover는 배경(`--bg-raised`)이나 텍스트 승급으로, "지금 활성"은 액센트로.
  hover에 액센트를 쓰면 활성 상태와 구분이 사라진다 (예외: 아이콘 단독
  버튼처럼 활성 개념이 없는 곳).
- 위험 동작은 2단계: 컨텍스트 메뉴의 danger 항목 → `role="alertdialog"`
  확인 다이얼로그에서만 `--danger` 확정 버튼.

## 9. 키보드 단축키 (M6-A)

| 키 | 동작 |
|---|---|
| ⌘T | 새 탭 메뉴 |
| ⌘W | 활성 탭 닫기 (탭 없으면 아무 일도 없음 — 창은 ⇧⌘W) |
| ⌘P | 선택된 과목의 빠른 파일 검색 |
| ⌘, | 설정 창 |
| ⌘1‥8 | n번째 탭 활성화 |
| ⌘9 | **마지막** 탭 (브라우저 관례. 9번째가 아니다) |
| ⌘R / ⌘⇧R | 새로고침 / 캐시 무시 새로고침 |
| ⌘L | 주소창 포커스 + 전체 선택 |
| ⌘F | 페이지에서 찾기 (Esc로 닫음) |
| ⌘D | 이 페이지를 즐겨찾기에 넣기/빼기 |
| ⌘+ / ⌘- / ⌘0 | 확대 / 축소 / 기본 크기 |
| ⌘⇧T | 닫은 탭 다시 열기 (최근 10개, 과목 전환 시 비움) |
| ⌘⇧[ / ⌘⇧] | 이전 / 다음 탭 (양끝에서 순환) |

**브라우저 전용 코드**(⌘R·⌘L·확대축소)는 브라우저 탭이 활성일 때만 동작한다.
PDF나 필기 위에서는 아무 일도 일어나지 않는다 — `activeBrowserTabId()`가 null을
돌려주면 그대로 끝난다. 게스트에서 재생된 코드는 **자기 탭 id를 들고 오므로**
활성 탭이 아니라 그 탭에 적용된다.

가드 규칙 (`src/renderer/src/app/shortcuts.ts`의 `resolveShortcut`):
- IME 조합 중(`isComposing`/keyCode 229)에는 아무것도 발동하지 않는다.
- meta 또는 ctrl 단독 코드만 인정 — alt/shift가 끼면 무효 (⌘⇧T ≠ ⌘T).
- **웹뷰 게스트가 포커스를 가진 동안엔 탭 수명(⌘T·⌘W·⌘9·⌘⇧T·⌘⇧[·])과
  브라우저 크롬(⌘R·⌘⇧R·⌘L·⌘F·⌘D·확대축소)만 동작한다.** 메인 프로세스가 게스트의
  `before-input-event`에서 가로채 `shortcut:passthrough` 푸시로 재생한다 —
  나머지(⌘P·⌘,·⌘1‥8)는 게스트 페이지의 키맵을 존중해 의도적으로 죽인다.
  ⇧ 코드 중 넘기는 것은 ⌘⇧R·⌘⇧T·⌘⇧[·]뿐이고, ⌘⇧B(새 브라우저 탭)와
  ⌘⇧M(새 필기)은 페이지에 남긴다.
- **패스스루 페이로드는 발신 게스트의 `webContentsId`를 싣는다.** 게스트는
  dockview 패널 DOM 밖 고정 레이어에 살고 포커스를 받아도 패널이 활성화되지
  않으므로, 이게 없으면 분할 화면에서 ⌘W가 엉뚱한 탭을 닫는다.
- macOS 기본 메뉴의 ⌘W(창 닫기)는 `src/main/menu.ts`가 ⇧⌘W로 옮겨
  두었기 때문에 ⌘W가 렌더러까지 내려온다. 메뉴를 손대면 이 전제가 깨진다.
- 입력 필드 안에서도 모든 코드는 동작한다 (텍스트 입력과 충돌하지 않는
  modifier 코드이므로).
