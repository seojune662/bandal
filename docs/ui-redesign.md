# 0.58 UI·UX 개편 검증 기록

기준 버전은 0.57.0 (`9354d0664590d899341f2d323b12d856b76cc8dc`)이다. Electron·React·TypeScript, 업무 IPC와 DB 구조를 유지했다. 사용자 테마 편집기와 Rust 전환은 포함하지 않는다.

## 구현

- 48px 전역 레일, 기본 240px 과목 사이드바, 작업 공간, 기본 288px 자료 패널. 44px 상단 영역의 사이드바 버튼은 접힌 상태에서도 같은 위치에 남는다.
- OS 시스템 글꼴, 무채색 표면, 선택 배경, 최소 패널 경계와 공통 포커스. 과목·오류·녹음·필기 색과 흰 PDF 종이는 유지한다.
- 과목 행과 드래그 처리를 분리하고 메뉴의 진입·닫기·포커스 복원을 공통화했다. 중복 제목, 하단 메뉴, 큰 즐겨찾기 빈 화면을 제거했다.
- PDF 기본 도구와 주석 작업 도구를 분리하고 추가 도형·내보내기, 필기 스타일을 팝오버로 묶었다. 비활성 과목·패널은 필기 단축키를 처리하지 않는다.
- 외형 설정을 별도 컴포넌트로 분리했다. 활성 테마는 `system | light | dark`이며 신규 기본값은 `system`이다. `sepia`, `high-contrast`는 light, `midnight`, `graphite`는 dark로 읽는다. 기존 팔레트와 플러그인 테마 값은 설정 호환에만 남기고 런타임 CSS와 적용 경로를 삭제했다.
- 모든 앱 렌더러가 설정 캐시로 최초 외형을 적용한 뒤 표시된다. 메인·설정·어시스턴트·미니 플레이어가 동일한 해석을 사용한다. 네이티브 창 배경도 변경을 반영한다.
- 이전 스타일 가이드를 [새 기준](STYLEGUIDE.md)으로 교체했다. CSS만 바꿔도 테마·탐색·설정·드래그·팝오버 검사를 선택한다.

## 성능 비교

2026-10-01, Apple M4 arm64 / macOS 26.2 (25C56), Electron 43.4.1. 동일 컴퓨터에서 두 production 빌드를 별도 임시 프로필로 순차 실행했다. 기준 소스는 Git archive로 분리했다. 시작 시간은 Electron 실행 요청부터 메인 셸과 적용된 테마가 준비될 때까지의 Playwright 관측 시간이며, 각 5회 중앙값이다. OS 파일 캐시를 비우지 않았으므로 시스템 콜드 부팅 수치는 아니다.

| 항목 | 이전 | 이후 |
|---|---:|---:|
| 시작 시간 중앙값 | 593.8ms | 565.8ms |
| 시작 설정 조회 | 8회 | 1회 |
| 탭 전환 P95, 30회 | 17.3ms | 17.2ms |
| 사이드바 개폐 P95, 30회 | 17.1ms | 17.9ms |
| PDF 스크롤 P95, 100쪽 문서 60회 | 17.5ms | 17.3ms |
| 같은 작업 후 GC JS 힙 | 18.41MiB | 17.36MiB |
| 과목 전환 P95, 100회 | 17.2ms | 17.6ms |
| 과목 100회 전환 후 GC 힙 증가 | 0MiB | 0MiB |

상호작용 시간은 이벤트 후 두 번의 animation frame까지를 잰 값으로 실제 프레임 시간의 하한을 포함한다. 차이가 작은 항목은 개선으로 해석하지 않는다. Chromium `performance.memory` 값은 정밀도가 제한되며, 0MiB는 이 검사에서 관측한 값이지 누수가 없다는 일반적 증명은 아니다. OS 프로세스 전체 RSS와는 구분한다.

중복된 부팅 설정 조회를 공유 캐시로 합친 것이 확인된 최적화다. 최근 과목 캐시, 백그라운드 작업 분리, 문서 지연 로딩과 자료 가상화는 유지했다. 과목 전환 P95 <150ms, 힙 증가 <32MiB, 50개 탭 복원 시 선택한 필기만 읽기, 10,000개 파일의 제한된 DOM 목록 검사를 통과했다. 원시 측정은 [JSON](ui-redesign-performance.json)에 보관했다.

재현:

```sh
pnpm build
BANDAL_UI_BENCHMARK=/tmp/bandal-ui.json pnpm exec playwright test -c e2e uiPerformance.spec.ts coursePerformance.spec.ts
# 기준 빌드: BANDAL_E2E_ENTRY=/path/to/baseline/out/main/index.js 추가
BANDAL_UI_ARTIFACTS=/tmp/bandal-ui pnpm exec playwright test -c e2e uiRedesign.spec.ts
```

## 검증 범위

- 타입 검사: main, renderer, web-demo. 테마·아이콘·설정·과목 메뉴·인증 진입·언어 캐시의 영향 단위 검사와 CSS 대비 검사.
- 테마: 신규 시스템 기본값, OS 모드 변경, 명시 선택, 이전 4개 테마 변환, 재시작, 주 창과 보조 창 동기화, 플러그인/팔레트 무시 및 기존 외형 설정 보존.
- 셸: 1024×640·1440×900, 긴 제목, 빈 목록, 과목 재정렬, 사이드바 접기·폭 조절·초기화, 탭·즐겨찾기·자료 드래그, 설정 카테고리, 120% 글자 크기, 메뉴 위치와 Escape 포커스 복원.
- 작업 화면: PDF 텍스트·확대·주석 스타일·내보내기 접근, 필기 서식, 화이트보드·지우개, Office 뷰어, 브라우저 포커스·팝업·로그인 프로필, AI 대화·승인·어시스턴트 메뉴, 학업 보드·달력 설정, 녹음 재생과 위젯.
- 배포: 동일 커밋의 CI 결과를 재사용하며 macOS·Windows 패키징된 앱에서 변경 영역 E2E를 실행한다. 서명·공증·업로드 무결성과 양 플랫폼 업데이트 피드는 릴리스 워크플로에서 확인한다.

OS 권한 승인, 실제 개인 계정 로그인·AI 서비스 연결·Apple 캘린더·메일 동기화는 자동 검증하지 않는다. 해당 E2E는 임시 데이터/모의 응답을 사용한다. 실제 기기의 OS 고대비 전환과 이전 설치판에서 업데이트를 설치·재시작하는 수동 절차는 별도 범위다. Windows 설치 파일은 프로젝트의 기존 배포 정책대로 미서명이다.
