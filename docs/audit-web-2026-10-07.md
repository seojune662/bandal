## 확인하여 수정한 문제

### 다른 과목 필기와 저장 전 초안이 내보내기에서 누락

기존 `exportNotes`는 기본 예시 과목만 필터링하고 영구 저장된 `data.notes`만 읽었다. 다른 체험 과목의 필기는 다운로드에서 빠졌고, debounce 전에 내보내거나 브라우저 저장 공간이 가득 차면 편집기에 보이는 최신 초안도 빠졌다. 저장 오류 문구가 내보내기를 안내하는 상황에서도 원본 초안을 복구할 수 없었다.

- 기존 정적 빌드에서 Playwright로 두 번째 과목의 노트를 만든 뒤 Storage quota 오류를 강제로 발생시키고 긴 초안을 입력했다. 실제 다운로드에는 두 번째 과목도 최신 초안도 없음을 확인했다.
- 모든 과목의 저장된 필기를 수집하고 열린 노트 session의 전체 Markdown snapshot으로 최신 내용을 덮어쓴다. 과목명과 파일 경로를 각 문서 앞에 기록한다.
- snapshot은 원본 문자열이며 AI context의 12,000자 제한을 적용하지 않는다. 빈 문서도 유효한 최신 내용으로 취급한다. 중복 패널에서는 지연된 peer 대신 현재 writer를 선택한다.
- 저장이나 flush를 성공 조건으로 요구하지 않는다. 내보내기는 동기 읽기와 Blob 다운로드여서 quota 실패 중에도 복구할 수 있다.
- 앱 수정: `noteSessionRegistry`의 선택적 snapshot accessor, `NoteTab` registration 한 줄, `web-demo/adapter.ts`의 `notesMarkdownForExport`.
- 회귀: 두 과목, quota 실패, 12,000자보다 긴 초안, stale duplicate, 빈 문서, 실제 다운로드 콘텐츠를 검사한다.

### 캡처와 라이브 데모의 출처를 불필요하게 동일시

`tests/site.spec.ts`는 demo, theme/catalog source, product capture, AI social capture의 commit이 모두 같아야 한다고 요구했다. 이 조건은 라이브 데모만 갱신하는 정상 릴리스를 막거나 변경되지 않은 스크린샷을 새 버전으로 재표기하게 만들 수 있었다.

- 각 artifact의 원래 버전·commit·촬영시각을 독립적으로 검증한다. 실제 배포 manifest 응답과 소스 파일이 일치하고 캡처 캡션에 그 캡처의 버전이 표시되는지도 확인한다.
- `ProductShot`의 기존 v0.69.0 캡처 표기를 유지한다. “현재 반달 화면”이라고 단정하던 대체 텍스트를 실제 캡처 설명으로 바꿨다.
- README에 원본 provenance 유지와 독립 갱신 절차를 명시했다. `public/product/capture.json`과 AI social 이미지/manifest는 수정하지 않았다.

### 체험 과목과 페이지 필기의 이름 변경 뒤 잘못된 파일 열기

- 다른 체험 과목의 기본 이름 필기를 변경해도 전역 `primaryNotePath`가 바뀌어 기본 PDF·필기 체험이 존재하지 않는 파일을 열었다. 변경 전 단위 회귀에서 이 잘못된 경로 변경을 재현했고, 기본 과목에 한해서만 기본 필기 경로를 갱신하도록 수정했다.
- demo rename도 실제 앱처럼 확정된 파일명으로 H1과 응답의 title/markdown을 맞추고 mtime을 단조 증가시킨다. `.MD` 대소문자도 처리한다.
- 이름이 바뀐 페이지 필기를 재방문할 때 고정된 seed 파일명 대신 실제 연결 기록의 target을 사용한다. 넓은 화면의 연결 pair와 작은 화면의 단독 필기에 함께 적용한다.
- `tests/web-demo/adapter.test.ts` 7개 및 web-demo를 포함한 타입 검사 통과. `tests/preview.spec.ts`에 다른 과목 rename→체험 전환과 연결 필기 rename→재방문 브라우저 회귀도 추가했다.

### 학습 기능의 도움말 경로 누락

현재 앱의 퀴즈·카드·영어 이어읽기는 변경내역에서 언급되지만 사용 안내 목차/본문에 없었다. 실제 `LearningCreateDialog`, `LearningReader`, `LearningReview`, 학습 생성 흐름을 기준으로 한·영 `#learning` 안내를 추가했다. 자료/AI 선택, 원문 출처, 답 변경 후 재평가, 카드 복습, 주제·수준·시간 설정, 단어장과 다음 글 찾기, 실패 시 재시도를 설명하며 설치 앱과 AI 연결 필요성을 구분했다.

### 모바일 PDF가 준비돼도 화면은 비어 있는 문제

최종 홈페이지 스크린샷의 영어 320px 데모에서 PDF 본문이 비어 있었다. iframe을 실제 화면으로 스크롤하고 canvas 생성과 텍스트 로드를 기다린 뒤 1.5초가 지나도 같아 캡처 시점 문제와 구분했다. iframe은 286×670px, 실제 `.dv-content-container`는 286×523.5px였지만 Dockview의 `.dv-render-overlay`와 presentation slot의 높이는 0이었다. retained 콘텐츠도 0×0으로 남아 내부 178×133px canvas를 잘랐다. canvas에 대한 Playwright `toBeVisible()`만으로는 이 상태를 잡지 못했다.

- Dockview 4.13.1의 `always` overlay는 실제 그룹의 크기를 비동기로 복사하지만 그룹 콘텐츠 자체의 resize를 관찰하지 않았다. 초기 preset의 RAF 지연만으로 해결되지 않았으며 그 임시 변경은 되돌렸다.
- 공통 `panelContentHost`가 실제 그룹의 직계 `.dv-content-container`를 측정해 workspace 기준 상대 좌표로 변환한다. 해당 영역에 ResizeObserver를 연결하고 group 변경 때 관찰 대상을 교체한다. 폐기 시 관찰자도 해제한다.
- 보이지 않는 탭과 0 크기 reflow는 마지막 유효한 크기를 유지한다. 이동 중 slot이 없는 구간은 측정하지 않으며 편집기 DOM과 미저장 내용을 보존한다.
- native browser는 live wrapper의 크기·가시성을 관찰하는 기존 경로를 유지한다. 그룹 콘텐츠와 overlay가 사용하는 원래 좌표 기준이 같음을 독립 검토했고 browser anchor 가시성 회귀도 통과했다.
- 공통 runtime 수정이므로 웹만의 임시 CSS 보정으로 배포하지 않는다. 이 변경은 v0.75.0 runtime에 포함됐으며 후속 PDF 복원 경합 수정까지 포함한 최종 목표 버전은 **v0.76.0**이다. desktop 설치 파일 검증·공개는 root가 수행한다.

### 초기 인쇄 메뉴 동기화가 설치 앱 전용 안내를 표시

데모 진입 직후 사용자 명령 없이 설치 앱 전용 toast가 표시됐다. `bandal-demo-unavailable` 이벤트를 초기 스크립트에서 수집해 `window:setPrintEnabled`가 네 번 호출되는 것을 확인했다. 이는 문서 활성 상태에 따른 native 인쇄 메뉴 상태 동기화였으며 실제 인쇄 요청이 아니었다.

웹 adapter에서 이 내부 상태 동기화만 성공 no-op으로 처리했다. 실제 지원하지 않는 사용자 기능에 대한 안내 경로는 유지한다. enabled/disabled 동기화가 안내 이벤트를 만들지 않는 단위 회귀와, 초기·복원 진입의 unsupported 이벤트가 0개인 실제 브라우저 회귀를 추가했다.

### 좁은 영어 화면에서 AI 체험 메뉴가 잘림

PDF 표시 문제를 고친 뒤 직접 확인한 320px 이미지에서 네 개의 scene 버튼이 한 줄에 배치돼 마지막 `AI example` 버튼이 화면 밖으로 잘리는 것을 발견했다. 480px 이하에서는 데모 scene 메뉴를 2열로 배치한다. 실제 앱 도구 레이아웃을 바꾸지 않으며, 모든 scene 버튼이 iframe 안에 완전히 보이는지 검사한다.

### 후속 연결 스크롤과 저장 위치 복원 경합

v0.75.0 macOS 패키지의 첫 연결 휠 검사 실패를 조사하며 두 경합을 통제 재현해 수정했다. 같은 값 `sync=true`의 metadata 재수신이 대기 중인 페이지 anchor를 지우지 않으며, 늦은 저장 위치 응답은 최신 사용자 휠·페이지 이동·배율 조작·peer 이동을 덮지 않는다. 정상 저장 배율의 실제 pageWidth 레이아웃 반영 뒤 최종 페이지로 이동하고, 최초 숨김/수명과 사용자 취소를 구분한다. 원래 macOS 실패와의 직접 인과는 미확정으로 남기며 자세한 재현과 desktop 회귀는 [편집 기능 감사](audit-editors-2026-10-07.md)에 기록했다.

웹 `demo-initial` 회귀도 reload 전에 해당 언어의 localStorage에 실제 workspace layout과 열린 panel이 저장됐음을 확인한다. 빠른 reload가 새 데모 초기화를 다시 검사하는 경우와 영구 저장 레이아웃 복원을 구분하기 위한 조건이다.
